# Agent 评估框架 — 技术设计文档

> 项目定位：一个自动化评估 AI Agent 输出质量的多维度评估框架，支持规则评估、LLM 评估和组合评估三种策略。

---

## 第一章 项目背景与价值

### 1.1 为什么做

随着大语言模型（LLM）驱动的 AI Agent 在问答、代码生成、工具调用等场景的广泛落地，如何**客观、可量化地评估 Agent 的输出质量**成为核心痛点：

- **人工评估成本高**：每次 Agent 迭代都需要人工逐条打分，难以规模化
- **评估标准不统一**：不同人对"好不好"的判断主观性强，缺乏一致性
- **缺乏自动化流水线**：无法在 CI/CD 中自动回归测试 Agent 性能
- **多维度需求**：单纯的准确率不够，还需评估相关性、完整性、连贯性等维度

### 1.2 解决方案

Agent Evaluator 提供了一套**开箱即用的评估框架**：

- 定义标准化的评估维度（Accuracy / Relevance / Completeness / Coherence）和权重体系
- 实现三种评估策略（规则 / LLM / 组合），兼顾速度与智能
- 提供数据集管理和基准测试运行器，支持一键跑完全部测试用例并生成摘要报告

### 1.3 面试话术

> "我在 Agent 开发过程中发现，每次修改 Prompt 或切换模型后，都需要人工验证输出质量，效率很低。所以我设计了这个评估框架，把评估抽象为**数据集 + 评估器 + 基准测试**三层。评估器采用了策略模式，支持规则评估（快、确定性强）和 LLM 评估（语义理解强、成本高），还可以通过 CompositeEvaluator 组合使用。基准测试层自动编排测试流程，按难度分组统计，方便做 A/B 对比和回归测试。"

## 第三章 核心模块设计

### 3.1 评估器模块 (`src/evaluator.py`)

这是框架的核心，采用**策略模式**实现三种评估策略。

#### 3.1.1 数据模型

所有数据结构使用 Python `dataclass` 定义，兼具类型安全和序列化能力：

```python
class EvalMetric(Enum):
    """评估指标"""
    ACCURACY = "accuracy"          # 准确性
    RELEVANCE = "relevance"        # 相关性
    COMPLETENESS = "completeness"  # 完整性
    COHERENCE = "coherence"        # 连贯性
    LATENCY = "latency"            # 延迟
    COST = "cost"                  # 成本

@dataclass
class TestCase:
    """测试用例"""
    id: str
    input: str                       # 用户输入
    expected_output: str             # 期望输出
    context: str = ""                # 上下文
    tags: List[str] = field(default_factory=list)
    difficulty: str = "medium"       # easy, medium, hard

@dataclass
class EvalResult:
    """单个评估结果"""
    metric: EvalMetric
    score: float           # 0-1
    explanation: str = ""
    metadata: Dict[str, Any] = field(default_factory=dict)
```

#### 3.1.2 评估报告与加权总分

`EvalReport` 是核心报告对象，`calculate_total()` 实现了加权总分计算：

```python
@dataclass
class EvalReport:
    test_case: TestCase
    actual_output: str
    results: List[EvalResult] = field(default_factory=list)
    latency: float = 0.0
    tokens_used: int = 0
    total_score: float = 0.0

    def calculate_total(self, weights: Dict[EvalMetric, float] = None):
        """计算加权总分"""
        if not self.results:
            return 0.0
        if weights is None:
            weights = {
                EvalMetric.ACCURACY: 0.4,
                EvalMetric.RELEVANCE: 0.3,
                EvalMetric.COMPLETENESS: 0.2,
                EvalMetric.COHERENCE: 0.1
            }
        total = 0.0
        total_weight = 0.0
        for result in self.results:
            weight = weights.get(result.metric, 0.1)
            total += result.score * weight
            total_weight += weight
        self.total_score = total / total_weight if total_weight > 0 else 0.0
        return self.total_score
```

**设计要点**：权重缺失时使用 `0.1` 作为兜底值，`total_weight` 累加确保归一化正确。

#### 3.1.3 RuleEvaluator — 规则评估器

基于字符串匹配的确定性评估，速度快、零成本：

```python
class RuleEvaluator:
    def evaluate(self, test_case: TestCase, actual_output: str) -> List[EvalResult]:
        results = []
        accuracy = self._check_accuracy(test_case.expected_output, actual_output)
        results.append(EvalResult(
            metric=EvalMetric.ACCURACY,
            score=accuracy,
            explanation="基于关键词匹配的准确性评估"
        ))
        relevance = self._check_relevance(test_case.input, actual_output)
        results.append(EvalResult(metric=EvalMetric.RELEVANCE, score=relevance, ...))
        completeness = self._check_completeness(test_case.expected_output, actual_output)
        results.append(EvalResult(metric=EvalMetric.COMPLETENESS, score=completeness, ...))
        coherence = self._check_coherence(actual_output)
        results.append(EvalResult(metric=EvalMetric.COHERENCE, score=coherence, ...))
        return results

    def _check_accuracy(self, expected: str, actual: str) -> float:
        """基于关键词交集的准确性评分"""
        expected_words = set(expected.lower().split())
        actual_words = set(actual.lower().split())
        if not expected_words:
            return 1.0
        matches = expected_words.intersection(actual_words)
        return len(matches) / len(expected_words)

    def _check_relevance(self, input_text: str, output_text: str) -> float:
        """输入与输出的词汇重叠率"""
        input_words = set(input_text.lower().split())
        output_words = set(output_text.lower().split())
        if not input_words:
            return 1.0
        overlap = input_words.intersection(output_words)
        return min(len(overlap) / len(input_words) * 2, 1.0)
```

**核心算法**：准确性用 `set intersection` 计算关键词覆盖率；相关性用输入-输出词汇重叠率（×2 上限为 1.0）；完整性用长度比；连贯性用完整句数。

#### 3.1.4 LLMEvaluator — LLM 评估器

通过 Prompt 让 LLM 做语义级别的评判：

```python
class LLMEvaluator:
    def __init__(self, llm_caller: Callable = None):
        self.llm_caller = llm_caller or self._mock_llm

    def evaluate(self, test_case: TestCase, actual_output: str) -> List[EvalResult]:
        prompt = self._build_prompt(test_case, actual_output)
        response = self.llm_caller(prompt)
        return self._parse_response(response)

    def _build_prompt(self, test_case, actual_output) -> str:
        return f"""请评估以下 AI Agent 的输出质量。
用户输入：{test_case.input}
期望输出：{test_case.expected_output}
实际输出：{actual_output}
请从以下维度评估（每项 0-1 分）：
1. 准确性  2. 相关性  3. 完整性  4. 连贯性
请以 JSON 格式返回：
{{"accuracy": 0.0, "relevance": 0.0, "completeness": 0.0, "coherence": 0.0, "explanation": "评估说明"}}"""
```

**设计亮点**：`llm_caller` 参数接受任意 Callable，可以无缝替换为 DeepSeek、GPT-4 等真实 API；默认 `_mock_llm` 用于开发测试。`_parse_response` 包含 JSON 解析失败的兜底处理。

#### 3.1.5 CompositeEvaluator — 组合评估器

策略组合模式，融合多种评估器的结果：

```python
class CompositeEvaluator:
    def __init__(self):
        self.evaluators = []     # List[(evaluator, weight)]

    def add_evaluator(self, evaluator, weight: float = 1.0):
        self.evaluators.append((evaluator, weight))

    def evaluate(self, test_case, actual_output) -> List[EvalResult]:
        all_results = []
        for evaluator, weight in self.evaluators:
            results = evaluator.evaluate(test_case, actual_output)
            for result in results:
                result.score *= weight       # 按权重缩放
                all_results.append(result)

        # 合并相同指标，取平均
        merged = {}
        for result in all_results:
            if result.metric not in merged:
                merged[result.metric] = []
            merged[result.metric].append(result.score)

        final_results = []
        for metric, scores in merged.items():
            avg_score = sum(scores) / len(scores)
            final_results.append(EvalResult(
                metric=metric,
                score=avg_score,
                explanation=f"综合 {len(scores)} 个评估器的结果"
            ))
        return final_results
```

**设计要点**：先按权重缩放各评估器分数，再对相同指标取均值，实现了加权融合。

#### 3.1.6 工厂函数

```python
def create_evaluator(eval_type: str = "rule") -> Any:
    """评估器工厂，支持 'rule' / 'llm' / 'composite'"""
    if eval_type == "rule":
        return RuleEvaluator()
    elif eval_type == "llm":
        return LLMEvaluator()
    elif eval_type == "composite":

@dataclass
class TestDataset:
    name: str
    description: str = ""
    test_cases: List[TestCase] = field(default_factory=list)

    def add_case(self, test_case: TestCase):
        """添加测试用例"""

    def get_cases(self, difficulty: str = None, tags: List[str] = None) -> List[TestCase]:

        cases = self.test_cases
        if difficulty:
            cases = [c for c in cases if c.difficulty == difficulty]
        if tags:
            cases = [c for c in cases if any(t in c.tags for t in tags)]
        return cases

#### 3.3.1 配置与结果数据类

@dataclass
class BenchmarkConfig:
    name: str = "Default Benchmark"
    repetitions: int = 1           # 每个测试重复次数
    timeout: float = 30.0          # 超时时间（秒）
    weights: Dict[EvalMetric, float] = field(default_factory=lambda: {
        EvalMetric.ACCURACY: 0.4,
        EvalMetric.RELEVANCE: 0.3,
        EvalMetric.COMPLETENESS: 0.2,
        EvalMetric.COHERENCE: 0.1
    })
```

#### 3.3.2 BenchmarkRunner 核心运行逻辑

```python
class BenchmarkRunner:
    def __init__(self, config=None, evaluator=None, agent_caller: Callable = None):
        self.config = config or BenchmarkConfig()
        self.evaluator = evaluator or RuleEvaluator()
        self.agent_caller = agent_caller or self._mock_agent

    def run(self, dataset: TestDataset) -> BenchmarkResult:
        result = BenchmarkResult(config=self.config)
        cases = dataset.get_cases()
        for i, test_case in enumerate(cases, 1):
            for rep in range(self.config.repetitions):
                report = self._run_single_test(test_case)
                result.add_report(report)
        result.finish()
        return result

    def _run_single_test(self, test_case: TestCase) -> EvalReport:
        start_time = time.time()
        actual_output = self.agent_caller(test_case.input)  # 调用 Agent
        latency = time.time() - start_time
        eval_results = self.evaluator.evaluate(test_case, actual_output)
        report = EvalReport(
            test_case=test_case, actual_output=actual_output,
            results=eval_results, latency=latency,
            tokens_used=len(actual_output.split())
        )
        report.calculate_total(self.config.weights)
        return report
```

#### 3.3.3 BenchmarkResult 多维统计

```python
class BenchmarkResult:
    def get_summary(self) -> Dict[str, Any]:
        total_score = sum(r.total_score for r in self.reports) / len(self.reports)
        avg_latency = sum(r.latency for r in self.reports) / len(self.reports)

        # 按难度分组统计
        difficulty_stats = {}
        for report in self.reports:
            diff = report.test_case.difficulty
            if diff not in difficulty_stats:
                difficulty_stats[diff] = {"count": 0, "total_score": 0}
            difficulty_stats[diff]["count"] += 1
            difficulty_stats[diff]["total_score"] += report.total_score
        for diff in difficulty_stats:
            stats = difficulty_stats[diff]
            stats["avg_score"] = stats["total_score"] / stats["count"]

        # 按指标统计
        metric_stats = {}
        for report in self.reports:
            for result in report.results:
                if result.metric.value not in metric_stats:
                    metric_stats[result.metric.value] = []
                metric_stats[result.metric.value].append(result.score)
        metric_avg = {k: sum(v)/len(v) for k, v in metric_stats.items()}

        return {
            "name": self.config.name,
            "total_cases": len(self.reports),
            "total_score": round(total_score, 3),
            "avg_latency": round(avg_latency, 2),
            "difficulty_stats": difficulty_stats,
            "metric_avg": metric_avg
        }
```

## 第四章 技术亮点

### 4.1 策略模式实现评估器解耦

三种评估器（Rule / LLM / Composite）遵循统一的 `evaluate(test_case, actual_output) -> List[EvalResult]` 接口，可随时切换或组合，符合**开闭原则**（对扩展开放、对修改关闭）。

### 4.2 加权融合的组合评估

`CompositeEvaluator` 先按权重缩放各评估器分数，再对同指标取均值。这种设计允许灵活配比——例如规则评估占 60%（保底）、LLM 评估占 40%（提升语义理解），兼顾速度和质量。

### 4.3 工厂模式 + 依赖注入

- `create_evaluator()` 工厂函数集中创建逻辑
- `LLMEvaluator.__init__` 接受 `llm_caller` 参数，解耦具体 LLM 实现
- `BenchmarkRunner.__init__` 接受 `agent_caller` 参数，Agent 可以是任意函数

### 4.4 多维统计与按难度分组

`BenchmarkResult.get_summary()` 自动按难度（easy/medium/hard）和指标维度统计，便于发现 Agent 的薄弱环节（例如"hard 用例平均分显著低于 easy"）。

### 4.5 纯 Python 标准库实现

核心模块仅依赖 `dataclasses`、`typing`、`enum`、`json`、`time`，零外部依赖即可运行，便于集成到任意项目。

## 第五章 面试常见问题

**Q1: 评估指标的权重是怎么确定的？**

> 权重基于业务重要性分配：准确性（40%）> 相关性（30%）> 完整性（20%）> 连贯性（10%）。权重通过 `BenchmarkConfig.weights` 字典配置，支持运行时自定义。`calculate_total()` 中还设置了 0.1 的兜底权重，确保新增指标不会导致除零。

**Q2: 规则评估器的准确性算法是什么？有什么局限？**

> 准确性使用 `set intersection` 计算期望输出与实际输出的关键词覆盖率。局限是只做词级匹配，不理解语义（例如"Python 是编程语言"和"编程语言 Python"会被判为相同）。因此提供了 `LLMEvaluator` 作为语义级补充。

**Q3: LLM 评估器怎么集成真实的 LLM？**

> `LLMEvaluator` 的构造函数接受 `llm_caller: Callable` 参数。只需传入一个接受 prompt 字符串、返回 JSON 字符串的函数即可。例如接入 DeepSeek：
> ```python
> def deepseek_caller(prompt):
>     response = httpx.post("https://api.deepseek.com/chat/completions", ...)
>     return response.json()["choices"][0]["message"]["content"]
> evaluator = LLMEvaluator(llm_caller=deepseek_caller)
> ```

**Q4: CompositeEvaluator 的融合策略是什么？为什么不用加权平均而是先缩放再平均？**

> 采用"权重缩放 + 同指标取均值"的两步策略：先将每个评估器的分数乘以其权重（缩放），再将相同指标的多个结果取算术平均。这比直接加权平均更灵活——不同评估器可能对同一指标给出不同权重的分数，缩放后再平均能更平滑地融合。

**Q5: 如何扩展新的评估指标？**

> 两步：(1) 在 `EvalMetric` 枚举中添加新指标；(2) 在评估器的 `evaluate()` 方法中添加对应计算逻辑。如果是 LLM 评估器，只需在 `_build_prompt` 的评分维度中加入新指标。

**Q6: 这个项目有多少代码量？用了什么技术栈？**

> 核心代码约 700 行 Python，分布在 4 个模块文件中。技术栈纯 Python 3.8+，使用 `dataclasses` 做数据建模、`enum` 做指标枚举、`json` 做序列化。外部依赖（rich, httpx, pydantic）在 requirements.txt 中声明，但核心评估逻辑不依赖它们。

**Q7: 如果要支持 A/B 测试，怎么设计？**

> 已有基础：`BenchmarkRunner` 接受 `agent_caller` 参数，可以用不同的 Agent 函数实例化两个 Runner，对同一数据集运行后对比 `BenchmarkResult.get_summary()` 的 `total_score` 和 `metric_avg`。后续可以封装 `ABTestRunner`，自动对比并输出差异报告。
